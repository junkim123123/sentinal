# Sentinel Persona Design Review Playbook

## 목적
- Sentinel의 최신 로컬/프리뷰 빌드를 6인 구매위원회 관점에서 점검한다.
- 비주얼 완성도만 보지 않고 신뢰감, 구조, CTA 흐름, 제품 실재감, category fit까지 함께 평가한다.
- 같은 템플릿으로 이후 프리뷰 URL에도 반복 적용할 수 있게 만든다.

## 리뷰 범위

포함 페이지
- 핵심 마케팅: `/`, `/product`, `/solutions`, `/pricing`, `/methodology`, `/about`, `/ai-roadmap`
- 전환/문의: `/contact`, `/demo`, `/consultation`, `/support`, `/support-request`, `/thanks`
- 제품 증거: `/dashboard`, `/reports`

제외 페이지
- `/privacy`
- `/terms`
- `404`
- sitemap, robots, opengraph 같은 SEO 시스템 페이지

## 페르소나별 기본 여정
- 경제적 의사결정자: `/` -> `/product` -> `/pricing` -> `/reports` -> `/contact`
- 조달 책임자: `/` -> `/product` -> `/solutions` -> `/demo` -> `/contact`
- 시장/전략 분석가: `/` -> `/product` -> `/dashboard` -> `/reports` -> `/demo`
- 컴플라이언스/트레이드 옵스: `/` -> `/methodology` -> `/product` -> `/support` -> `/support-request`
- 데이터/BI 연계 담당: `/` -> `/product` -> `/dashboard` -> `/reports` -> `/consultation`
- 회의적인 확장 구매자: `/` -> `/about` -> `/solutions` -> `/pricing` -> `/contact`

## 평가 Rubric

모든 페르소나는 아래 8개 항목을 공통으로 채점한다.

| 항목 | 질문 | 채점 기준 |
| --- | --- | --- |
| 첫인상 신뢰감 | 첫 화면만 보고도 전문 팀처럼 느껴지는가 | 1 = 저가형/불안, 3 = 무난, 5 = 바로 공유 가능 |
| 포지셔닝 명확성 | Sentinel이 무엇을 누구에게 파는지 명확한가 | 1 = 모호, 3 = 대체로 이해, 5 = 한 문장으로 설명 가능 |
| 정보 구조/스캔 용이성 | 길어도 핵심 구조가 빨리 잡히는가 | 1 = 피곤, 3 = 읽으면 이해, 5 = 훑기만 해도 구조가 보임 |
| 비주얼 완성도/프리미엄감 | 레이아웃, 타이포, 카드 밀도, 대비가 프리미엄 B2B에 맞는가 | 1 = 싸 보임, 3 = 무난, 5 = 고급스럽고 통제됨 |
| 근거와 증거의 설득력 | 방법론, 샘플, 데이터 포인트가 신뢰를 주는가 | 1 = 주장만 있음, 3 = 일부 설득, 5 = 내부 설득에 충분 |
| 제품 실재감 | 대시보드/리포트/아티팩트가 실제 제품처럼 보이는가 | 1 = 컨셉 수준, 3 = MVP처럼 보임, 5 = 바로 데모 가능한 수준 |
| CTA 흐름과 전환 마찰 | 다음 행동이 자연스럽고 분기 구조가 납득되는가 | 1 = 헷갈림, 3 = 움직일 수 있음, 5 = 망설임 없이 진행 가능 |
| 산업/역할 적합성 | 내 산업/역할의 맥락이 반영되어 있다고 느끼는가 | 1 = 나와 무관, 3 = 어느 정도 맞음, 5 = 내 문제처럼 보임 |

## 실행 절차

### 1. 데스크톱 리뷰
- 대상 페이지 전부를 1440px 이상 폭 기준으로 점검한다.
- 각 페르소나는 자신의 기본 여정을 먼저 보고, 이후 필요한 보강 페이지를 추가 확인한다.
- 결과는 `latest-review.md`의 페르소나 점수표와 페이지별 코멘트에 기록한다.

### 2. 모바일 리뷰
- 반드시 `/`, `/product`, `/contact`, `/demo`, `/dashboard`를 모바일로 추가 확인한다.
- 모바일에서는 다음만 별도 체크한다.
- hero 높이와 스크롤 피로
- CTA 버튼 폭과 반복
- 표/카드/폼의 압축도
- sticky 요소 또는 시선 흐름 문제

### 3. 이슈 우선순위 규칙
- `P1`: 전환 저하, 신뢰 손상, 제품 실재감 약화처럼 구매 판단에 직접 타격이 있는 문제
- `P2`: 이해 속도 저하, CTA 마찰, category fit 혼선처럼 설득력을 약하게 만드는 문제
- `P3`: polish, 일관성, 세부 밀도처럼 개선 가치가 있지만 당장 구매를 막지는 않는 문제

### 4. 코멘트 표기 규칙
- 모든 이슈 코멘트는 아래 형식을 따른다.
- 형식: ``[`/page` | 페르소나명 | P1/P2/P3] 코멘트``
- 여러 페이지가 걸리면 ``[`/contact,/demo` | 경제적 의사결정자 | P1] ...``처럼 쓴다.
- 교차 페르소나 이슈는 ``다수`` 또는 구체 페르소나 목록으로 적는다.

## `latest-review.md` 기록 형식

각 페이지는 아래 순서를 유지한다.

1. `좋았던 점 3개`
2. `이탈/의심 포인트 3개`
3. `놓친 정보 2개`
4. `CTA 반응`
5. `즉시 고칠 디자인 이슈`
6. `메시지 이슈`
7. `신뢰 이슈`

추가 규칙
- 각 페이지의 1~3번은 반드시 개수를 맞춘다.
- 4~7번은 최소 1개 이상 기록한다.
- `/`, `/product`, `/contact`, `/demo`, `/dashboard`는 `모바일 관찰`을 추가한다.

## 재사용 프롬프트 템플릿

### 시스템 프롬프트
```text
당신은 Sentinel의 잠재 구매자이며, 주어진 페르소나 배경과 구매 동기로 사이트를 검토한다.
미학 평가가 아니라 실제 구매 위험과 신뢰 판단을 기준으로 말한다.
각 평가는 디자인, 정보 구조, 제품 실재감, CTA 흐름, 산업 적합성에 대한 판단을 포함해야 한다.
막연한 취향 표현 대신 "왜 내부 공유를 망설이게 되는지"를 설명한다.
출력은 한국어로 한다.
```

### 입력 슬롯
```text
- 페르소나 정의:
- 대상 환경: 최신 로컬 또는 프리뷰 URL
- 대상 페이지:
- 현재 디자인 목표:
- 검토 디바이스: desktop 또는 mobile
- 금지사항: 브랜드 색 변경 제안 금지 / 카피 전면 재작성 금지 / 구현 난도 무시 금지 등
```

### 출력 형식
```text
1. 8개 rubric 점수표
2. 첫 감정 반응 3문장
3. 가장 설득된 지점 3개
4. 가장 의심되는 지점 3개
5. CTA 반응
6. 개선 제안
7. 최종 구매 의향
```

## 빠른 재실행 체크리스트
- 최신 브랜치와 커밋을 문서 상단에 기록했다.
- 포함/제외 페이지를 다시 확인했다.
- 6개 페르소나 모두 점수표를 작성했다.
- 15개 대상 페이지 섹션을 모두 채웠다.
- 모바일 5개 페이지를 별도로 점검했다.
- 교차 페르소나 통합 이슈를 최소 10개 이상 뽑았다.
